## Plan

**Objective.** Stop `Repo_Current_State.md` from being writable, and therefore from being wrong.

**In scope.** Generate its mechanical facts from `git`, `roadmap.yaml`, `pyproject.toml`, and
`scripts/`, leaving one human paragraph: the next recommended ticket and why.

**Out of scope.** The `registry`, `scope`, and `frozen` lint checks, which are T0031.4.

## Summary

`scripts/docs_build.py` now renders four generated regions into `docs/Repo_Current_State.md`,
extending the machinery T0031.2 built for the three entry-fed registers rather than adding a
second generator.

The ticket named seven facts to derive. They do not all have the same character, and the
implementation splits them on that difference rather than pretending they are alike:

- **Tree-derived and gated.** `milestones` from `roadmap.yaml`, `dependencies` from
  `pyproject.toml`, and `scripts` from the module docstrings under `scripts/`. These are pure
  functions of the committed tree, so the existing `generated` lint check gates them exactly as it
  gates the entry-fed regions, with no new check and no CI change.
- **Clone-derived and deliberately not gated.** `snapshot` carries branch, baseline commit,
  unmerged branches, and worktree count. These describe a clone rather than a commit: they differ
  between a developer machine and CI, so a check that must pass on both can never verify them.
  `--snapshot` writes the region, `stale()` skips it, and `--check --snapshot` is rejected with an
  explanatory error rather than silently producing a false failure.
- **Not derived at all.** Build status stays hand-written. It is the result of running commands,
  not a reading of any of the three sources the ticket names, and generating it would have meant
  either running the suite inside the documentation build or inventing a cache for it. This is a
  deliberate deviation from the ticket text and is carried as a follow-up, not as done.

The hand-written prose those regions replaced was removed rather than left beside them, which is
the point: two copies of a fact is the failure mode this milestone exists to remove. The narrative
that went with it was already recorded in the completion reports and the ticket archive.

`Repo_Current_State.md` measured 190 lines against a 175 cap, so the cap moved to 210. Following
the repository's own rule that a cap is set from measurement, the superseded cap paragraph in
`docs/README.md` was rewritten in place rather than appended to, keeping that file inside its own
150-line cap.

## Risks

- **The `snapshot` region is unverified by construction.** Nothing detects a stale git block; it is
  only as fresh as the last `--snapshot` run. This is the accepted cost of not gating a clone-local
  fact, but it means the region can silently describe a clone from three merges ago. T0031.4's
  `frozen` check is the natural place to require integration to have run it.
- **`main` is assumed to exist locally.** `render_snapshot` computes unmerged branches against
  `main`; in a clone that only has `origin/main`, that git call returns nothing and the region
  reports zero unmerged branches rather than failing. It degrades quietly.
- **Milestone rows are only as honest as `roadmap.yaml`.** Deriving status from the registry moves
  the failure from "the snapshot is stale" to "the registry is wrong", which is the better failure
  but not no failure.
- **A wrapped bullet can grow a false nested bullet.** `wrap` indents continuations by two spaces,
  so a continuation that happens to begin with `- ` renders as a nested list item. It cannot
  currently happen - the wrapped content is backticked names - but a commit subject containing
  ` - ` near the wrap column would do it.
- **Cap headroom is thinner than it looks.** At 190 against 210, roughly ten more dependencies or
  scripts will breach it, and the breach will arrive through an unrelated ticket adding a package.
