**Ticket:** T0020.4 — Gated cron-activation sequence. **Blocked on T0020.2.** Gates: **D2, D5, D6, D10**.
**Audience:** the maintainer (repo admin + Neon/Render/GitHub owner). **Not a coder task** — every step here

## 0. Preconditions — do NOT start until these hold

The sub-ticket order `.1 → .2 → .3 → .4` exists to force a safe sequence. The cron *cannot* fire before
T0020.1 (GitHub fires `schedule:` only from the **default branch**, so the workflow had to reach `main`),
and it *must not be trusted* before T0020.2 puts the serving-path honesty fixes **live**.

| # | Precondition | Why it gates cron activation | State |
|---|---|---|---|
| P1 | **T0020.1 done** — `main` reconciled (`bcc81db`, PR #29); the workflow now lives on `main`. | `schedule:` only fires from the default branch. Until the workflow is on `main`, activation is structurally impossible. | ☐ confirm `git log origin/main` carries `.github/workflows/ingestion.yml` |
| P2 | **T0020.2 done** — Render's deploy branch = `main`; a redeploy has put the **T0019.8 data-derived `/ready` date** and the **T0019.10 `get_job_details` column allowlist** on the live site. | Once the cron can expire a row (`is_active=false`), the *live* path would otherwise serve the pre-T0019.10 `SELECT *` lifecycle leak and the pre-T0019.8 static `/ready` date **against an expiring corpus**. Repointing Render first closes that window. | ☐ confirm live UI shows the T0019.10 surface (see T0020.2 runbook check C) |
| P3 | **T0020.3 (recommended, not strictly blocking)** — CI merge gate live on `main`. | Protects the reconciled artifact so a later change can't silently break the serving path the cron feeds. | ☐ optional |

> **If P2 has not landed by the first 02:00 UTC window after activation, do not activate.** A cron that expires
> rows while the live demo still serves pre-fix code is the exact hazard this ordering prevents.

## 2. D5 — run T0019.5 safety checks B–E against a live Docker Postgres

Source of truth: `docs/Manual_Verification_Guide.md` → **### T0019.5** (§1127+). Reproduced here for a single sitting.
**Local Docker Postgres only — never run any of these against Neon.** (mypy note in that guide's Check A is stale:
T0020.3 baselined the two prior errors, so `uv run mypy` is now green.)

**Check B — green run against a correct local DB** (Docker Postgres up, `HEALTHCHECKS_URL` unset):
```
uv run python -m src.services.ingestion.loader
```
Expect: `ingestion.schema_ok` → `ingestion.completed` with all six numbers (`fetched`, `raw_upserted`, `clean_loaded`, `skipped`, `expired_count`, `pages_failed`) → `ingestion.ping_skipped`. `echo $?` = `0`.
- Result (paste `ingestion.completed` line): `{"fetched": 114, "raw_upserted": 114, "clean_loaded": 114, "skipped": 0, "expired_count": 27, "pages_failed": 0, "event": "ingestion.completed"}` → `ingestion.ping_skipped`, exit 0. **PASS** (2026-07-22, coder session, local Docker PG)

**Check C — drift is caught, nothing is written** (scratch DB only):
```
docker compose exec -T postgres psql -U internhunter -d postgres -c "CREATE DATABASE internhunter_drift TEMPLATE internhunter;"
docker compose exec -T postgres psql -U internhunter -d internhunter_drift -c "ALTER TABLE clean_jobs RENAME COLUMN location TO location_old;"
DATABASE_URL="postgresql+psycopg://internhunter:internhunter@localhost:5433/internhunter_drift" uv run python -m src.services.ingestion.loader; echo "exit=$?"
```
Expect: `ingestion.schema_drift` naming `location` missing / `location_old` unexpected → `ingestion.aborted` → `exit=1`, with **no** page-level log lines (it aborts before fetching). Then confirm untouched + clean up:
```
docker compose exec -T postgres psql -U internhunter -d internhunter_drift -c "SELECT COUNT(*) FROM clean_jobs;"
docker compose exec -T postgres psql -U internhunter -d postgres -c "DROP DATABASE internhunter_drift;"
```
- Result (exit code + drift log): `ingestion.schema_drift {"missing": ["location"], "unexpected": ["location_old"]}` → `ingestion.aborted` → `exit=1`, **no** fetch/page lines. Scratch `clean_jobs` untouched (141 rows), scratch DB dropped. **PASS** (2026-07-22)

**Check D — yield floor blocks the clean write** (local DB; temporarily set `safety.min_yield` in `config/ingestion.yaml` above the run's actual yield):
```
uv run python -m src.services.ingestion.loader; echo "exit=$?"
```
Expect: `ingestion.yield_floor_breached` with both numbers, `exit=1`, **no** `ingestion.completed`. `SELECT COUNT(*) FROM clean_jobs;` unchanged; `raw_jobs` grew or held (raw landing is allowed). **Revert `min_yield` to `20` afterwards.**
- Result: `ingestion.yield_floor_breached {"fetched": 114, "min_yield": 999}` → `ingestion.aborted` → `exit=1`, **no** `ingestion.completed`. `clean_jobs` unchanged (141→141); `raw_jobs` held (141, idempotent upsert). **PASS** (2026-07-22)   ☑ reverted `min_yield` to `20`

**Check E — the dead-man ping path** (no real healthchecks.io account needed):
```
HEALTHCHECKS_URL="https://httpbin.org/status/200" uv run python -m src.services.ingestion.loader
```
Expect `ingestion.ping_sent` after the summary. Then point at a failing URL (`https://httpbin.org/status/500` or an unroutable host) and confirm `ingestion.ping_failed` logs as a **warning** while the process still exits `0`.
- Result (both branches): success — `HEALTHCHECKS_URL=https://postman-echo.com/post` → `ingestion.ping_sent`, exit 0. failure — a failing/slow URL (`httpstat.us/500`, also seen with `httpbin.org/status/200` timing out) → `ingestion.ping_failed` logged as **warning**, process still `exit=0`. **PASS** (2026-07-22)

☑ **D5 cleared** (B–E all pass against a live Docker Postgres) — 2026-07-22, coder session. NOTE: this clears the local-Postgres gate; the Neon/production gates (D6, activation) remain the maintainer's.
