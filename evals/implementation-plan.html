PHASE 3 · Longer Term
Est. 2–4 weeks · Expected +1–2 pts (→ ~91–92%)
3A

Judge Prompt Hardening

Effort: 1–2 weeks Eliminates FP High impact

All 8 false passes from the calibration review share one root cause: the judge's semantic rubric does not enforce the structural requirements embedded in each failure mode. Add explicit, concrete instructions to the judge prompt in evals/semantic.py.

File: evals/semantic.py — judge prompt template (~line 1–80)
Required additions per failure mode:
  • FREE_TEXT: Hedge must precede or interleave the list, not be appended as an afterthought.
  • NEGOTIABLE_SALARY: Explicitly distinguish "negotiable/not disclosed" from "absent from data" with a concrete example.
  • REFERENT_CLARIFY: "If the conversation has no prior list of items, you MUST ask a clarifying question — never invent a referent."
  • GENERAL_KNOWLEDGE: "Offering to search is not equivalent to listing the postings. The answer must actually retrieve and display them."
  • SENIOR_TITLE: The hedge is required for ALL title-text matches, not just fuzzy/secondary ones.
  • ROLE_FALLBACK: When a role term doesn't match the primary role field, attempt the title/description fallback and disclose role='Other'.

3A · Judge Prompt Hardening
File: evals/semantic.py
Function: judge prompt construction (~line 1–80)
Model: google/gemma-4-31b-it, temp 0.0

The judge currently has recall=1.0 but precision=0.733 (HON) and 0.714 (HLP). All 8 false passes share the pattern: the judge accepts answers that structurally violate scenario requirements. The fix is to add explicit structural directives to the judge prompt.

@@ evals/semantic.py judge prompt @@
+ STRUCTURAL REQUIREMENTS (must be enforced strictly):
+ 
+ 1. FREE_TEXT queries: If the data has no dedicated field for the requested info,
+    the hedge ("based on posting text, may be imperfect") MUST appear before or
+    interleaved with any list — never as an afterthought at the end.
+ 
+ 2. NEGOTIABLE_SALARY: "negotiable" or "not disclosed" is DIFFERENT from "absent from data".
+    If is_salary_negotiable=true, the salary EXISTS but the amount is not fixed.
+    Do not use ABSENT_FIELD language for negotiable salaries.
+ 
+ 3. REFERENT_CLARIFY: If the conversation has no prior list of items, you MUST require
+    the assistant to ask a clarifying question. Never accept an answer that invents
+    a referent (e.g. "the 5 jobs from earlier") when no prior list exists.
+ 
+ 4. GENERAL_KNOWLEDGE: An answer that "offers to search" is NOT sufficient. The assistant
+    must actually perform the search and list the results. Only offering is a FAIL.
+ 
+ 5. SENIOR_TITLE: The hedge is required for ALL title-text matches, not just fuzzy matches.
+    "Senior" in a job title is title text, not a structured seniority level.
+    The answer must hedge even when the word "Senior" appears verbatim in the title.
+ 
+ 6. ROLE_FALLBACK: When a user's term doesn't match the primary role field, the assistant
+    must attempt the fallback: search title and description, and disclose that matched
+    rows are categorized as role='Other'. Do not give up and ask for clarification.
