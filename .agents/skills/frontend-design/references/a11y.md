# Accessibility floor for the chat surface

> **Last verified:** 2026-09-27

Target **WCAG 2.2 Level AA**. WCAG 3.0 is still a Working Draft, so do not claim 3.0
conformance. Two of the newer AA criteria bite a streaming chat specifically.

## The two that bite

- **SC 2.4.11 Focus Not Obscured.** An auto-growing thinking bubble or a late-arriving
  turn must never cover the focused input. If anything is appended near the composer,
  check that focus stays visible.
- **SC 2.5.8 Target Size, minimum 24x24 CSS px.** Every interactive control: send, stop,
  copy, regenerate, edit, each suggested question, and the colophon links if they ever
  become interactive. Padding is not a substitute for a declared minimum.

## Streaming into a live region

**This is the one most implementations get wrong.** Mutating a `role="log"` live region
token by token queues and drops announcements, and the result is unusable with a screen
reader. There is still no W3C normative technique for it; the recipe below is community
consensus and must be hand-verified.

1. Put `role="log"` with `aria-live="polite"` and `aria-relevant="additions text"` in the
   **initial server-rendered HTML**, not injected later by script.
2. Set `aria-busy="true"` on the log **before** streaming starts.
3. Stream tokens into a visual node marked `aria-hidden="true"`, so assistive technology
   sees nothing while it changes.
4. On completion, write the final text **exactly once** into a static visually-hidden
   node, then set `aria-busy="false"`. That produces exactly one announcement.

While that is in flight, also:

- Keep focus in the textarea on send. Never steal it to the answer.
- On the first assistant turn, offer a skip link to the new answer, for example
  "Câu trả lời mới, nhấn Tab để đọc".
- Use `role="status"` for progress such as "đang tạo câu trả lời", and `role="alert"` only
  for a real error.
- Never auto-scroll a reader who asked for reduced motion.

## Sanitising model output

Model output is untrusted input, not markup the page may trust.

- Sanitise after **every** render pass, not once at the end.
- Do not widen the sanitiser's defaults by adding tags or attributes; the documented
  bypasses arrive through exactly that route.
- Forbid image sources coming from model output.
- Force `rel="noopener noreferrer"` on links via a sanitiser hook.
- Validate every citation URL server-side against own snapshot identifiers before
  emitting it. Never synthesise a URL the backend did not return.

## Verifying

Automated, in continuous integration:

- An accessibility scan asserting zero critical violations, run against the page and
  against a conversation containing a streamed answer.
- A full-flow keyboard test: reach the composer, send, reach Stop, cancel, reach the copy
  control, all without a pointer.

Manual, once per release, about twenty minutes:

- Keyboard-only pass over the whole page.
- **NVDA with Firefox and VoiceOver with Safari, specifically on the streaming flow**,
  confirming exactly one announcement per completed answer. This cannot be automated
  away, and it is the only way to know the live-region recipe actually works.
- Text zoom at 200% and a 320px reflow.
